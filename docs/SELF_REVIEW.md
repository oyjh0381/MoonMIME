# MoonMIME 本地验收与代码自审

审查基线：v0.1.0 本地发布候选；日期：2026-09-08。审查流程采用 `osc2026-guide` 的本地严格门禁。GitHub、Gitlink、Mooncakes 和远端 CI 依项目所有者指令暂缓，因此不计为已满足。

## 【1. 总体评价】

本地实现已具备真实可用的完整闭环：`Bytes` 输入、邮件头及媒体字段解释、递归实体树、传输解码、字符集显示、查询、报告、Native CLI、示例、测试、CI 配置和申报书。核心错误均使用稳定类型表示，兼容恢复受到明确限制。

正确性高风险区域为 multipart 定界、递归资源消耗、Base64/QP 尾部规则、RFC 2047/2231 组合和不可信附件名。当前分别通过精确行锚定扫描、深度/实体/体积限制、规范尾位检查、严格/兼容测试以及“不落盘”CLI 边界控制。剩余主要风险是 v0.1 仅支持内存解析、字符集有限、不能递归解析 transfer-encoded `message/rfc822`；这些均已在 README 与 Scope 明示。

本地结论：通过发布候选级验收。公开交付结论：待 GitHub/Gitlink、远端 CI 与 mooncakes.io 发布完成后才能最终通过比赛硬验收。

## 【2. 算法与性能分析】

当前实现先线性扫描邮件头，再按 Content-Type 解释实体。每层 multipart 对其有界正文执行一次行扫描，识别精确 delimiter，并递归解析子实体；解码和查询均与目标正文或实体数量线性相关。

- 邮件头：`O(h)` 时间，`O(f)` 元数据空间，其中 `h` 为邮件头字节，`f` 为字段数。
- 递归解析：最坏 `O(n*d)` 时间，`d` 为嵌套深度；默认 `d <= 16`。空间为 `O(n+e)`，因为原始 `Bytes` 被保留且存储 `e` 个实体/字段元数据。
- Base64、Quoted-Printable：`O(b)` 时间及最多 `O(b)` 输出空间。
- 查询：全树枚举和附件/正文选择为 `O(e)`；路径查找为 `O(d)`。
- JSON/文本报告：`O(e+a+g)`，其中 `a` 为附件数、`g` 为诊断数。

主要瓶颈是完整输入驻留内存和嵌套 multipart 的重复包围扫描。v0.1 通过 32 MiB 输入和 16 层深度限制控制风险。流式状态机可将大消息峰值内存降至 `O(chunk + metadata)`，但会显著增加跨 chunk 边界、源区间与错误恢复复杂度，不适合在当天 v0.1 内仓促加入，建议作为 v0.2 独立设计。

## 【3. 具体优化步骤】

1. 已将字节结构与字符串显示分离，目的为避免非 UTF-8 载荷损坏，预期效果是附件与未知字符集始终保持原始字节可追踪。
2. 已采用行锚定 delimiter 扫描并拒绝前缀/中缀伪匹配，目的为保证 multipart 分段正确性。
3. 已在解析前验证资源限制，并在递归、字段、参数、边界、叶体和解码输出处即时检查，目的为限制不可信输入的 CPU/内存放大。
4. 已增加 `DecodeBudget`，同时执行单叶和跨叶累计解码预算；失败解码不扣减预算。
5. 已补充严格/兼容、边界、异常、嵌套、四后端及 CLI 测试，目的为在发布前发现语义和平台差异。
6. 后续若实现流式解析，应先固定事件协议与 chunk 不变量，再以现有一次性解析器作为差分 oracle，最后进行大规模内存和吞吐基准。

## 【4. 推荐修改后的代码】

本轮审查已直接落实两项必要修改：共享解码预算位于 `transfer/budget.mbt`；Content-Disposition 错误类别修复位于 `media/parser.mbt`。完整代码已纳入提交历史，不另提供可能与仓库漂移的复制片段。

接口生成文件由 `moon info` 产生并提交，用于检查公开 API 漂移。所有格式调整由 `moon fmt` 完成。

## 【5. 测试建议】

已覆盖正常输入、空/极限范围、异常语法、兼容恢复、嵌套消息、累计预算、JSON 转义与四后端构建。发布前及后续版本还建议：

- 使用公开、许可证清晰且去隐私化的 MIME corpus 做差分测试；不得把真实私密邮件提交到仓库。
- 对 boundary、encoded-word、RFC 2231 和 transfer decoder 增加基于属性的随机测试。
- 构造接近 32 MiB、1,000 实体、16 层嵌套的压力测试，记录峰值内存和耗时。
- 在 Ubuntu/Windows 远端 CI 上复核 Native CLI，并在发布后运行 README 安装示例。
- 每次 MoonBit 工具链升级后重跑格式、全目标 check/test/build、API 生成和 CLI 烟雾测试。
